# Output contract

Scale detail to the request. Write in the user's language (English by default) with clickable official sources. If your environment cannot write files, return the report and the ledgers in your reply instead of skipping them.

## Scope and verdict

For full audits also deliver one ledger per platform (apple.json, google.json) using strict-mode.md and rules.json, with the validator result, coverage counts, unresolved rejection inventory and evidence gaps. Do not claim automated review approval. Distinguish internal evidence-gate requirements from store requirements. Record exact source/observation references and every locale; summarize individual runtime test cases and results.

Record date/app/platform/version/build/account type/territories/locales and inspected evidence. State inaccessible console/build/runtime areas.
Choose blocked / incomplete evidence / no blockers found in inspected scope. Do not equate a clean scope with guaranteed approval.

## Findings

| ID | Platform | Status / severity | Evidence / location | Rule / source | Fix | Verification |
| --- | --- | --- | --- | --- | --- | --- |
| ... | Apple or Google | PASS / FAIL / UNKNOWN / N/A; severity for FAIL | Observed fact, build and locale | Official section/link/access date/effective scope | Exact code/field/document change | Reproducible check and observed result |

Never fill placeholders as inspected facts. List FAIL and material UNKNOWN findings in the table; summarise the rest in one coverage line per status (for example "N/A: C15 no child audience, C16 no user content") instead of repeating the ledger. Separate review-message evidence, public policy and inference.

## Action order

Group fixes by where they are made (code, store console, legal pages, account), using the issue area from the ledger.

1. Submission/account blockers.
2. Metadata/legal-page changes and locale coverage.
3. Build/runtime fixes and necessary device/purchase tests.
4. Missing evidence and the smallest useful request.

For authorized work, report actual changes/tests and leave incomplete checks open. Include reviewer drafts when useful without implying they were sent.

## Document preparation

When requested, prepare app-specific privacy policy, EULA/terms selection, subscription disclosures, deletion instructions, review notes and declaration worksheet as applicable. Mark verified inputs and unresolved placeholders. Inventory data type, collection point, processor/recipient, purpose, platform, sharing/linkage/tracking, retention/deletion and consent. Do not mechanically translate one store's labels into the other.

For batch audits, use app/platform/build rows and shared issues with explicit affected apps; do not propagate factual answers such as no ads/no gambling/no data collection without evidence.
